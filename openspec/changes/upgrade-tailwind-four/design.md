## Context

See proposal.md for motivation. The UI has Tailwind 3 via `ui/postcss.config.js` with autoprefixer, three `@tailwind` directives in `theme.css`, and an otherwise empty JS Tailwind config with content globs/class dark mode. Vite already owns the UI build. `.nvmrc` is Node 24.

The current inventory found bare `rounded` on Labels/detail chips, checkboxes and grid editors; `focus-visible:outline-none` across navigation/forms; explicit ring widths (`ring-1`/`ring-2`) with no explicit ring color; many explicit theme border colors plus default-dependent controls. Search and editor/settings inputs use default placeholders. Buttons rely on preflight cursor behavior. SVAR CSS is global and its app token/viewport overrides are in `theme.css`. No `dark:` utilities, deprecated opacity utilities or space/divide utilities were found in the inspected application sources.

## Goals / Non-Goals

Preserve existing appearance and `.dark` behavior while changing the dependency/build integration. No palette changes, focus-color redesign, layout refactor, browser-compatibility layer, new test framework or spec delta. Screenshot evidence is required by the issue; no browser images have been captured during scoping.

## Decisions

- **Routine integration default:** Use Tailwind 4 with matching `@tailwindcss/vite`, preserving the existing React/Vitest Vite configuration. Replace the old entry with `@import "tailwindcss"`. Remove the superseded PostCSS config, empty Tailwind JS config and direct autoprefixer/PostCSS dependencies that served only that pipeline. The [official upgrade guide](https://tailwindcss.com/docs/upgrade-guide) recommends the dedicated Vite plugin, which also handles imports/prefixing; keeping both pipelines duplicates processing.
- Preserve the literal `:root`/`.dark` palette selectors and the current class toggle. Since the application has no `dark:` utilities, no unused custom dark variant is needed. Keep vendor token mapping and the 350px grid viewport. Capture grid editor/focus styles because Tailwind 4's native layers can interact with the globally imported vendor CSS; do not replace the grid or its stylesheet.
- Use the [official utility mappings](https://tailwindcss.com/docs/upgrade-guide#renamed-utilities) for actual usages: bare rounded to rounded-sm and outline-none to outline-hidden. Preserve explicit ring widths, but measure their old resolved colors/opacity before migration; the default ring color changes in v4. Add only the class or compatibility CSS needed for the inventoried border/ring/placeholder/button defaults. Use recorded v3 values where v4 palette values differ, without turning the existing palette into a new theme. No compatibility rule is justified solely by an unused item in the guide.
- Capture a baseline before dependency edits, then repeat with identical browser, viewports, data and UI state. Use Labels, Template detail with YAML expanded, Import with populated/editable grid, and Settings with forms visible at 1440x1000 and 390x844, both themes. These cover chips/cards, focus utilities, inputs, preview/YAML, responsive shell and vendor grid. Capture keyboard Tab focus on a Labels control and a Settings field in both themes and widths; include grid focus while capturing Import. Record resolved ring/outline/border/placeholder styles beside screenshots.
- No browser executable/Playwright cache was found in the inspected host paths. During implementation use a temporary Playwright capture script/browser installation under run tooling, with scripts, version details, deterministic fixture responses and PNGs in `.agent-runs/`; do not add a production dependency or permanent screenshot suite. Playwright's [screenshot API](https://playwright.dev/docs/screenshots) supplies the needed capture operation. Serve the actual built UI with its vendor CSS; DOM snapshots alone cannot show the rendered defaults.
- Review before/after images and computed styles, fix migration differences, and record the comparison in a run artifact. Screenshot capture/compare artifacts make the requested evidence reviewable; no checklist item claims that opening an image by itself proves equivalence. Preserve behavior rather than accepting an unexplained visual difference under this dependency issue.

## Risks / Trade-offs

The migration targets Tailwind 4's documented modern-browser baseline (Safari 16.4, Chrome 111, Firefox 128); the repository states no older-browser requirement. Existing theme/grid tests cover tokens and dimensions, not computed utility styles, so retain them and add browser evidence rather than duplicating them with source-string tests.

A clean `npm --prefix ui ci` after the manifest/lockfile update is part of acceptance, followed by lint/test/build. No new unit test is needed for a class rename. If another selected proposal has already changed screens, capture that current UI as the baseline rather than reverting its functionality.
