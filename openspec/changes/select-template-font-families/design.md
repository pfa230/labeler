## Context

See proposal.md for motivation. `TextRaw`, `LayoutItem::Text` and conversion have no family field. Template admission calls `TemplateContent::validate`; cloning default-instantiated text in `src/templates.rs` also enumerates its fields. Measurement caches only Inter bytes and requires both `wght` and `opsz`; `compile_paged` independently searches fonts for each engine. Typst's global text setting is Inter. Those independent paths cannot implement selected-family fitting consistently.

The pinned Typst 0.15.1 `FontBook::select` already selects a face by family, style, stretch and weight, accounting for variable axes; typst-as-lib 0.17.0 accepts loaded `Font` objects through its builder's `fonts` method. These local APIs were inspected, rather than assuming a newer API.

## Goals / Non-Goals

Use one font inventory for template validation, shaping and Typst. No discovery API, UI picker, font upload, font hot reload, family interpolation, fallback-family list, italic/stretch controls or Nerd Font patching is required. A regular JetBrains Mono variable font serves label text without adding terminal icon glyphs.

## Decisions

- **User decisions:** Ship Source Sans 3, JetBrains Mono and Roboto Condensed; keep Inter as default. Load custom files additively from `{LABELER_CONFIG_DIR}/fonts` (`/config/fonts` in Docker), on restart. An image-only directory cannot serve custom fonts without replacing the shipped directory or rebuilding.
- **User decision:** Authors use the family names Typst registers, case-insensitively. The selected Roboto Condensed binary is named `Roboto` by Typst, so templates use `font: Roboto`. Use the same normalized names for validation, measurement and emission, without a Labeler alias table or custom matcher.
- **Routine defaults:** `font` is a literal normalized family name matched through Typst's family lookup. No filename aliases. Preserve `Inter` as the public default even though its variable metadata uses `Inter Variable`. Exclude custom faces whose normalized family name equals a bundled family name, case-insensitively, from both the inventory and FontBook, so a mounted file cannot replace a bundled face. Ordering alone cannot enforce precedence because Typst ranks variant distance before book order. Use normal style/stretch and Typst's existing weight matcher for static and variable faces; a custom matching algorithm could choose different bytes from emission.
- Replace the Inter-only byte cache and per-compile filesystem searches with a process-lifetime inventory of loaded font bytes and a shared FontBook. Supply those same loaded fonts to compilation and use the book's selected face/index for rustybuzz/ttf-parser measurement. The inventory contains only bundled fonts and custom-directory fonts; disable Typst's embedded-font inclusion so it cannot add other selectable families. Initialize through the shared validation/render path so the service and catalog-index binary do not depend on a particular main entry point. A missing custom directory simply contributes no fonts. Retaining only file paths would make deletion or replacement change emission while measurement uses cached bytes.
- Carry the literal field through raw/domain/conversion, default-instantiation cloning and normal template validation. Use existing template-invalid reporting for an unavailable family; no new reason slug. Existing quarantine/write behavior already specifies the response, so it needs no duplicate delta. Unusable custom files do not contribute a family. After restart a removed family is therefore an unknown family, and the existing registry quarantine behavior applies.
- Thread the selected face through layout, candidate-size search, wrapping, shortening, cap-height/leading and emitted text options. Use only axes the face supplies, matching Typst's clamping. The old Inter-specific axis prerequisite is replaced, not retained as a special case: all three selected additions lack `opsz`, and static custom fonts have neither axis. Reuse the existing `cap_height` helper, which already mirrors Typst's derivation when the face lacks a cap-height metric. Extend #254's pre-fitting character check to this face. Existing sizing/ink rules remain the algorithm; only their font input changes.

## Font selection evidence

The attended research compared upstream binaries and independent reviews/community discussions before the user accepted the set. Source Sans 3 gives a humanist text face, JetBrains Mono gives explicit identifiers and punctuation, and Roboto Condensed gives moderate space savings. Each adds a different role rather than a near-duplicate of Inter.

- [Atkinson Mono comparison](https://www.anthes.is/font-comparison-review-atkinson-hyperlegible-mono.html) finds strong letter disambiguation in Atkinson and stronger punctuation/bracket distinctions in JetBrains; [Pimp my Type's Next review](https://pimpmytype.com/font/atkinson-hyperlegible-next/) discusses its small-text weights and spacious character. These are independent observations, not comparative thermal-print evidence.
- [Community discussion of Atkinson](https://news.ycombinator.com/item?id=44647190) raises the cost of its expanded forms; [small-label typography discussion](https://www.reddit.com/r/graphic_design/comments/xrf0aa/) favors consistent strokes, high x-height and moderate condensation. [An independent coding-font comparison](https://anarc.at/blog/2024-05-29-playing-with-fonts-again/) discusses glyph ambiguity and narrow mono alternatives. Screen preferences do not establish physical label readability.
- Local FreeType specimens at 180/300 dpi covered 8/10/12 pt and weights 400/700, grayscale and thresholded output. At matched capital height, Source Sans 3's sample was about 3% narrower than Inter and Roboto Condensed about 15% narrower. JetBrains Mono and Source Code Pro share a 0.6-em advance, while JetBrains has taller lowercase at the same point size. Atkinson Next/Mono and Intel One Mono binaries lacked the sampled Greek/Cyrillic coverage; coverage is a benefit here, not a newly imposed script requirement. DINish/Barlow Condensed and Iosevka offer greater compression, with a stronger narrow appearance or larger bundle cost.
- Upstream regular variable files inspected: Source Sans 3 646,340 bytes, JetBrains Mono 187,208 bytes, Roboto Condensed 371,616 bytes, totaling 1,205,164 bytes before licenses. Obtain them with their upstream licenses from [Adobe](https://github.com/adobe-fonts/source-sans), [JetBrains](https://github.com/JetBrains/JetBrainsMono) and [Google Fonts Roboto Condensed](https://github.com/google/fonts/tree/main/ofl/robotocondensed); record exact version/source and actual packaged size in the implementation commit message body. No new Rust dependency is needed.

## Risks / Trade-offs

Changing the face must change all fitting metrics together. Use an alternate-family specimen that actually differs from Inter to expose a hard-coded measurement path; use the existing rendering/ink helpers rather than a new harness. Static regular/bold custom faces exercise matching separately from variable axes. Compare implicit and explicit Inter output to preserve the default.

The research specimens were FreeType output, not Labeler/Typst or physical print tests. No claim of superior thermal-print readability is made.

The unmapped-character refusal is already part of the current Fonts requirement. Carry that rule into the selected-face contract. It must not reintroduce fallback outside the ink guarantee. Planning artifacts do not install fonts or change application behavior.
