1. **[P1] Grid clicks steal focus from the proposed textarea/select controls.** [design.md:38](/home/pfa/projects/labeler/.worktrees/issue-389/openspec/changes/issue-389-make-batch-grid-cells-editable-without-a/design.md:38) assumes the vendor ignores clicks inside controls, but its exemption checks only `closest("input")`. Textarea/select clicks dispatch `focus-cell` ([vendor:1487](/home/pfa/projects/labeler/ui/node_modules/@svar-ui/react-grid/dist/index.es.js:1487)), which focuses the cell wrapper ([vendor:223](/home/pfa/projects/labeler/ui/node_modules/@svar-ui/react-grid/dist/index.es.js:223)). I reproduced this with installed SVAR 2.7.3: clicking a focused custom textarea changed `document.activeElement` from `TEXTAREA` to `DIV[role=gridcell]`. The keyboard suppression at [design.md:74](/home/pfa/projects/labeler/.worktrees/issue-389/openspec/changes/issue-389-make-batch-grid-cells-editable-without-a/design.md:74) does not address clicks. Revise the event-handling design and add interaction coverage proving textarea/select controls retain focus and remain operable.

2. **[P2] The multiline design contradicts the retained contract for editable text cells.** [design.md:104](/home/pfa/projects/labeler/.worktrees/issue-389/openspec/changes/issue-389-make-batch-grid-cells-editable-without-a/design.md:104) preserves the multiline indication for read-only cells and otherwise relies on textarea rendering. However, [spec.md:311](/home/pfa/projects/labeler/.worktrees/issue-389/openspec/changes/issue-389-make-batch-grid-cells-editable-without-a/specs/template-inputs/spec.md:311) explicitly requires newline indication for **every** control, including single-line text controls holding imported multiline values. The proposed `input type=text` strips newlines from its displayed value; I verified `first\nsecond` displays as `firstsecond`. Define how editable single-line controls preserve the visible continuation indication and untouched stored value, and cover that case explicitly.

3. **[P2] Values native controls cannot represent have no complete presentation-and-correction contract.** [design.md:95](/home/pfa/projects/labeler/.worktrees/issue-389/openspec/changes/issue-389-make-batch-grid-cells-editable-without-a/design.md:95) requires an offset-bearing date to display as text, while [spec.md:250](/home/pfa/projects/labeler/.worktrees/issue-389/openspec/changes/issue-389-make-batch-grid-cells-editable-without-a/specs/template-inputs/spec.md:250) requires its date control always to exist. The plan never explains how these coexist or how the operator replaces that value. It also drops the published general text fallback ([current spec:1170](/home/pfa/projects/labeler/.worktrees/issue-389/openspec/specs/template-inputs/spec.md:1170)), leaving malformed numeric and checkbox values unspecified. Native date/number inputs display unrepresentable values as empty; retaining the underlying value alone therefore misrepresents what will submit. Specify the retained-value display, operable replacement control, and explicit-change boundary for these cases before implementation.
