Both screens immediately flag missing required values ([Connect.tsx:226](/home/pfa/projects/labeler/.worktrees/issue-389/ui/src/pages/Connect.tsx:226), [Import.tsx:155](/home/pfa/projects/labeler/.worktrees/issue-389/ui/src/pages/Import.tsx:155)). Consequently, an initially missing required value—or one cleared during editing—loses its only editing control and leaves the batch blocked. Revise the contract to keep the control operable alongside its diagnostic, with coverage for filling an initially invalid cell and clearing then refilling one.

2. **[P1] The keyboard design relies on an incorrect reading of SVAR’s handlers.** [design.md:63](/home/pfa/projects/labeler/.worktrees/issue-389/openspec/changes/issue-389-make-batch-grid-cells-editable-without-a/design.md:63) assumes the input check preserves native arrow behavior. In the installed `grid-store` version matching the lockfile, [dist/index.js:2](/home/pfa/projects/labeler/ui/node_modules/@svar-ui/grid-store/dist/index.js:2), ArrowUp/ArrowDown call `preventDefault()` **before** returning for `isInput`; the input detector also excludes `SELECT`. Thus textarea vertical navigation and numeric stepping are suppressed, while select arrows can invoke grid navigation. Removing editor registration does not disable these handlers. The plan needs an explicit strategy to prevent grid hotkeys from consuming control keystrokes, plus tests covering textarea, number and select controls; the proposed Tab test cannot establish this behavior.
