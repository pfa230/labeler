## 2. Keyboard, focus, and accessibility

- [x] 2.1 Suppress grid-store hotkeys for controls: each always-on control stops propagation of `ArrowUp`/`ArrowDown`/`ArrowLeft`/`ArrowRight` (and `Home`/`End` where relevant) and `LabelGrid` intercepts `hotkey` via `api.intercept("hotkey", …)` to suppress when target is `INPUT`/`TEXTAREA`/`SELECT` inside an always-on cell, preserving native `textarea` vertical movement, number stepping, and `select` navigation without grid cell navigation
- [x] 2.2 Preserve pointer and focus on controls: each always-on `TEXTAREA`/`SELECT`/`INPUT` stops propagation of `mousedown`/`click` and of `onFocus` (bubbling focus) so the vendor click handler (`closest("input")` check at `react-grid/dist/index.es.js:1487` → `focus-cell` at `:223`) and wrapper bubbling focus handler (`:249`) do not move focus to `DIV[role=gridcell]`; do not inspect `focus-cell` target (unsupported, carries only `row`/`column`/`eventSource`); ensure initial focus lands on the first editable cell without a preview column and that subsequent clicks and `Tab`/`Shift+Tab` keep `document.activeElement` on the intended control
- [x] 2.3 Synchronize `aria-readonly` on each data-cell wrapper with actual per-row editability after removing `editor` (SVAR derives it from `editor` at `:256`): set `false` for operable controls (has entry and not `list`/`image` and not `disabled`) and `true` for missing entry, `list`, `image`, and `disabled`, updating on transitions into/out of `disabled` without remount, per WAI-ARIA grid guidance

## 3. Presentation, multiline, and unrepresentable values

- [x] 3.1 Style editable cells as bordered inputs on surface colour at rest vs plain text for read-only (`list`/`image`/`disabled`/missing entry), distinguishable without hover/focus, using a class (e.g., `border border-input bg-background`) vs `inertStyle`
- [x] 3.2 Keep invalid cells repairable: an empty required cell renders its operable control alongside the `⚠ <error>` marker (`aria-describedby`/`title` plus visual `⚠`) rather than replacing the control, so an initially invalid cell and a cell cleared during editing can be filled and the marker clears on next validation
- [x] 3.3 Render multiline indication for every control: `textarea` and read-only cells show `first line +N` with `title`; for editable `text` holding `first\nsecond` (whose `input` would show `firstsecond`) render operable single-line input showing `first` with `+1` adornment and `title` holding full stored value, preserving stored newline until an explicit edit replaces it
- [x] 3.4 Render values the native control cannot represent as operable empty/unset control plus adjacent text adornment of the raw stored value (`title`/`aria-describedby` and visible text) with explicit-change boundary: `date`/`datetime` offset-bearing `2026-09-01T12:00:00Z`, `integer`/`number` non-numeric, `checkbox` malformed, and general fallback from `spec.md:1170`; rendering/focusing without explicit change preserves raw value, explicit typing/selecting/checking replaces it and clears adornment
