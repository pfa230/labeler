## Why

The batch grid (`ui/src/components/LabelGrid.tsx`, used by `ui/src/pages/Connect.tsx` and `ui/src/pages/Import.tsx`) only becomes editable on a double click. SVAR's grid has exactly one mouse trigger for its inline editors, `dblclick -> exec("open-editor")` (`node_modules/@svar-ui/react-grid/dist/index.es.js:1481-1485`), plus F2 on the focused cell, with no configuration flag for single-click or always-on editing. A row in a batch grid is a form and a form's fields are editable when you look at them; a hidden gesture between the operator and every cell is the wrong default for this screen.

Implements #389.

## What Changes

- **BREAKING** Grid cells render their editing control directly and always on, instead of opening an editor over the cell on a gesture. The control in the cell is the editor; no double click or F2 is required. The controls stay what `cellInput` already reports per row and per column.
- Every input control the batch grid draws today keeps its type and validation: `text`, `textarea`, `select`, `checkbox`, `integer`/`number`, `date`, `datetime`. `list` and `image` entries stay read-only, as `template-inputs` requires for this screen.
- Read-only while a batch is in flight (`disabled`) still holds for every cell. Per-row editability keeps coming from `cellInput`, not from the column.
- `registerInlineEditor` and the `editor` column predicate become dead once nothing opens an editor; they are removed rather than leaving two mechanisms.
- **Keyboard**: Tab and Shift+Tab walk cells in DOM order and that is the whole keyboard story. No custom focus code, no Enter-moves-down, no arrow navigation between cells; arrow keys move the caret inside the field. The grid windows its rows, so Tab reaches the end of the rendered window and stops rather than scrolling on, and that is accepted. This is a loss against today where arrow keys walk cells until a double click opens an editor; the installed `grid-store` still calls `preventDefault()` for ArrowUp/ArrowDown even when `isInput` (INPUT/TEXTAREA) and excludes SELECT from `isInput` entirely, so LabelGrid explicitly suppresses grid hotkeys when focus is inside an always-on INPUT/TEXTAREA/SELECT (stop-propagation on the control plus `intercept("hotkey")` suppression), preserving native textarea vertical movement, number stepping, and select dropdown navigation without reintroducing grid navigation.
- **Appearance**: An editable cell draws a bordered input on the surface colour at rest, not on hover or focus. Editable and read-only cells (a `list` entry, an `image` entry, every cell while a batch is in flight) are told apart by looking, without clicking anything. Read-only cells keep rendering as plain text. An empty required cell keeps its control operable alongside the `⚠` marker (via `aria-describedby`/`title`), so an initially invalid cell and a cell cleared during editing remain repairable while the run stays blocked.
- **Focus, multiline, and unrepresentable values**: Clicks and focus inside an always-on `TEXTAREA`/`SELECT` retain the control (the vendor otherwise dispatches `focus-cell` for anything but `INPUT` and the wrapper refocuses on bubbling `focus`; `focus-cell` carries only `row`/`column`/`eventSource` so target inspection is unsupported, so each control stops propagation of `mousedown`/`click`/`onFocus`); initial focus lands on the first editable cell without a preview column and Tab/Shift+Tab keep focus on the control; multiline indication (`first line +N` with `title`) applies to every control including an editable `text` cell holding an imported `first\nsecond` (whose `input` would otherwise show `firstsecond`); and a value the native control cannot represent (offset-bearing date, non-numeric number, malformed checkbox) is shown as an operable empty/unset control plus an adjacent text adornment of the stored raw value, with an explicit-change boundary so rendering/focusing alone does not mutate it; each data-cell wrapper's `aria-readonly` is synchronized with actual editability (`false` for operable, `true` for missing/`list`/`image`/`disabled`) since SVAR derives it from the removed `editor` property.
- No change to `POST /api/batch`, `POST /api/templates/{id}/inputs`, or the template schema. No new wire fields.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `template-inputs`: "A screen renders the reported inputs and decides nothing else" — grid cells are always-on controls rendered through the column `cell` template rather than through an overlay editor opened on a gesture; Tab/Shift+Tab navigation, loss of arrow-key cell navigation, always-on appearance, removal of the `editor` predicate/`registerInlineEditor` mechanism, and read-only cases for `list`/`image`/`disabled` are restated.

## Impact

- `ui/src/components/LabelGrid.tsx`: remove `registerInlineEditor`, the seven `*Editor` components, the `editor` column predicate and `init`'s `update-cell` intercept adaptation; render live controls from `cell` (existing `PreviewCell`/`ActionsCell` pattern), keep `cellInput` and `disabled` handling; style bordered inputs for editable cells vs plain text for read-only; add `stopPropagation` on Arrow keys and on `mousedown`/`click`/`onFocus` at each control plus `api.intercept("hotkey", …)` suppression when target is INPUT/TEXTAREA/SELECT so grid-store does not consume textarea vertical movement/number stepping/select navigation, with `onFocus` propagation suppression (not `focus-cell` target inspection, which is unsupported as `focus-cell` carries only `row`/`column`/`eventSource`) so clicks/focus inside textarea/select retain the control and initial focus lands on the first editable cell without a preview column; synchronize each data-cell wrapper's `aria-readonly` with actual per-row editability (`false` for operable, `true` for missing/`list`/`image`/`disabled`) since SVAR derives it from `editor` (`:256`); render `text` multiline as `first +N` with `title` alongside input and render offset-bearing date / non-numeric / malformed checkbox as empty control plus text adornment with explicit-change boundary.
- `ui/src/components/LabelGrid.test.tsx` (and/or `ui/src/pages/Connect.test.tsx`, `ui/src/pages/Import.test.tsx`): new coverage per control type asserting the control is present at rest, `list`/disabled render no control, invalid cells keep control alongside `⚠` (fill initially invalid, clear-then-refill), click inside textarea/select retains focus and operability via `mousedown`/`click`/`onFocus` propagation suppression (not `focus-cell` target inspection), initial focus on freshly mounted grid's first editable cell without preview column plus subsequent clicks and Tab/Shift+Tab keep focus on intended control, multiline `text` holding `first\nsecond` shows `+N` and preserves value until explicit edit, unrepresentable date/number/checkbox shows text adornment plus operable empty control with explicit-change boundary, `aria-readonly` is `false` for operable cells and `true` for missing/`list`/`image`/`disabled` with transitions into/out of `disabled`, and keyboard (Tab moves focus, Arrow keys inside textarea/number/select move caret/step/options without moving grid focus).
- No Rust, no API, no template change.
