1. **Major — the canonical example cannot render the promised pills under the unchanged sizing contract.** The repeated container and its nested text omit `size`/`to` (`proposal.md:23-31`). Non-container items require one of them (`src/convert.rs:60-65,111-114`), while an extent-less container defaults to `[fill, fill]` (`openspec/specs/layout-sizing/spec.md:965-968`). An ordinary packed fill container consumes the entire flow frame, causing subsequent instances to overflow (`openspec/specs/flow-layout/spec.md:202-209`). This contradicts the three-pills scenario (`specs/repetition/spec.md:154-158`) and the decision that flow behavior remains unchanged (`design.md:177-185`). The plan needs valid, explicit sizing—likely `[content, content]` for both pill and text—and scenarios that pin it.

2. **Major — the HTTP error reason contradicts the accepted issue scope and remains undecided.** The issue requires every repetition refusal submitted through a template write to return `template_parse_failed` (`.agent-runs/issue-319.md:116-124`). The proposal nevertheless says the issue’s settled contract is carried unchanged (`proposal.md:86-90`) while later allowing either `template_parse_failed` or `template_validation_failed` “as the stage decides” (`proposal.md:168-173`). That is observable API behavior, not an implementation detail. Moreover, scoped token refusals inherit `template_validation_failed` from the published interpolation contract (`openspec/specs/interpolation-tokens/spec.md:142-146`), whereas repetition’s structural refusals delegate to list-parameter terms (`specs/repetition/spec.md:44-47`). The artifacts must choose one contract consistent with the issue and specify how every refusal reaches it.

3. **Major — the new container field violates the first-touch rule.** The frozen schema’s container field list is still authoritative (`docs/SPEC.md:516-520`), and both `AGENTS.md:19-27` and `openspec/config.yaml:61-70` require an ADDED first-touch requirement to name the exact frozen section it supersedes and state the complete replacement contract. The repetition requirement introduces `repeat:` (`specs/repetition/spec.md:9-13`) but never supersedes the §4.1 container field list. Consequently the frozen exhaustive list and the proposed schema disagree after archive.

4. **Moderate — the promised diagnostic path is absent from two normative refusals.** The proposal says all nine refusals name the offending item’s layout path (`proposal.md:49-63`). The scoped join and format refusals require only that the token be named (`specs/interpolation-tokens/spec.md:54-66`; `specs/repetition/spec.md:225-233`). Those requirements do not preserve the proposal’s path guarantee, leaving implementation and tests free to omit it. The artifacts must either normatively require the item path for those refusals or narrow the proposal’s claim.

5. **Major — the design’s resource-risk mitigation is incompatible with existing trim semantics.** The design proposes materializing an expanded sequence with a cloned parameter map per instance (`design.md:112-126`) and claims label overflow bounds nested expansion because `trim` stops packing (`design.md:200-204`). Although packing stops, every trimmed active child must still be sized and evaluated and may still raise errors (`openspec/specs/flow-layout/spec.md:549-569`). Thus nested repeats can create a Cartesian workload independent of what fits on the label. The design needs a truthful resource analysis and an implementation strategy addressing that workload without silently imposing the instance cap the issue rejects.

VERDICT: REVISE
