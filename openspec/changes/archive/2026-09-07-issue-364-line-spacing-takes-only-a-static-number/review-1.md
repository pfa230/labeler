1. **[P1] Non-finite inputs cannot reach the proposed bounds check.** [design.md:147](/home/pfa/projects/labeler/.worktrees/issue-364/openspec/changes/issue-364-line-spacing-takes-only-a-static-number/design.md:147) claims `"NaN"`, `"inf"` and `1e300` reach the numeric resolver and produce `line_spacing_param_invalid`, as required by [the delta:138](/home/pfa/projects/labeler/.worktrees/issue-364/openspec/changes/issue-364-line-spacing-takes-only-a-static-number/specs/text-line-spacing/spec.md:138). However, request parameter resolution runs first ([src/render/mod.rs:741](/home/pfa/projects/labeler/.worktrees/issue-364/src/render/mod.rs:741)). Its number coercion converts these values to `f32` and then calls `serde_json::json!` ([src/render/mod.rs:122](/home/pfa/projects/labeler/.worktrees/issue-364/src/render/mod.rs:122)), which converts non-finite values to null ([Serde documentation](https://docs.rs/serde_json/latest/serde_json/enum.Value.html#impl-From%3Cf32%3E-for-Value)). The proposed resolver therefore receives null and returns `request_body_invalid` before the bounds check ([src/render/helpers.rs:218](/home/pfa/projects/labeler/.worktrees/issue-364/src/render/helpers.rs:218)). Numeric non-finite defaults lose their value even earlier, before default coercion ([src/render/mod.rs:531](/home/pfa/projects/labeler/.worktrees/issue-364/src/render/mod.rs:531)). The design needs a concrete way to preserve enough information to deliver the promised errors without changing unrelated numeric references. Verification must exercise the complete single-label and batch request paths; testing the numeric helper directly would miss this failure.

2. **[P2] The delta contradicts the existing batch atomicity contract.** [The delta:97](/home/pfa/projects/labeler/.worktrees/issue-364/openspec/changes/issue-364-line-spacing-takes-only-a-static-number/specs/text-line-spacing/spec.md:97) says a refusal becomes a row failure “rather than failing the batch.” The capability it invokes explicitly requires any failed label to fail the entire request with `422 BatchInvalid`, collecting indexed failures and producing no output ([batch-validation/spec.md:40](/home/pfa/projects/labeler/.worktrees/issue-364/openspec/specs/batch-validation/spec.md:40)). Replace that sentence with the existing atomic behavior: pitch failures appear in `details.failures`, the overall response is `422 BatchInvalid`, and no labels are downloaded or printed. Add a mixed valid/invalid-row scenario asserting that outcome.
