### Non-blocking

**1. Two endpoints gained a `500` their OpenAPI does not describe.** `get_template` (`src/api.rs:1164-1167`) and `template_inputs` (`:1293-1297`) list only 200/404 (and 422) in `responses(...)`, but both now fail with `AppError::internal` when `resolve_datetime_formats` fails (`:1175-1177`, `:1319-1321`) — a failure mode the delta makes normative (`specs/template-inputs/spec.md:1096-1099`). `put_template` and `update_template_group` do document 500. Precedent cuts the other way for `thumbnail`, which has the same two reads and also omits it, so this is a pre-existing inconsistency this change widens rather than introduces.

**2. Task 6.4's slider clause is checked but not performed.** The task named the checkbox, select **and** slider branches; the first two now read only `value` (`ui/src/components/ParamInput.tsx:185`, `:207`), while the slider still substitutes at `:129` (`(spec.default as number | undefined) ?? spec.min ?? 0`). Round 4 argued the `spec.default` form is the truthful one and this round restored it, which I agree is better than `min ?? 0` — but the line is unreachable in-tree either way (`isSlider` requires `hasDefault` at `:121-123`, `ParamInput` has exactly one call site at `FieldForm.tsx:100`, and `PrintForm.tsx:26-31`/`:46-49` seed every entry publishing a default), so nothing distinguishes the three spellings. The defect is the checked box, not the code.

**3. Task 7.6's second half cannot fail.** `issue_262_inputs_every_label_carries_same_default` (`src/lib.rs:10561`) uses `default: hello`, a literal, so both labels agree under any implementation including one that re-resolves per label. The first half is covered cross-endpoint only for the failure case (`inputs_endpoint_infallible_for_unresolvable_default`, `:9154`); the delta's scenario `specs/template-inputs/spec.md:130-135` uses a *resolving* `{vars.base}`, and no test reads that from both endpoints under one snapshot. Carried from round 4 #6, still open.

**4. Pre-existing, not introduced here: neither grid seeds cells from `default`.** `specs/template-inputs/spec.md:1039-1042` says both grids "keep seeding and submitting each entry's `default`", but `Import.tsx` and `Connect.tsx` read `input.default` nowhere — only `required` and `default_error`. The sentence and its scenario are unchanged in substance from the base spec (`openspec/specs/template-inputs/spec.md:547-548`, `:830-833`), so this gap predates the change and is out of its scope. Worth an issue rather than a fix here.
