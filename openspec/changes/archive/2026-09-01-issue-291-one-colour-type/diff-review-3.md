**Blocking findings.**

1. **`colour-vocabulary`'s quarantine requirement is unimplemented on all three fields, and text regressed.** The requirement states "The reported error SHALL name the file, the layout path of the offending item, and the field", with scenarios naming the `background` field and the `color` field. The actual error for `background: chartreuse` is `yaml error at layout[0]: layout[0]: layout: unknown colour 'chartreuse' at line 6 column 3` — file and layout path, no field [verified by run]. Identical for `stroke.color` and for `text.color`. On `HEAD` the text case emitted `invalid ink 'chartreuse': expected a named colour or '#'-prefixed hex` [verified by run], which named the field, and the shipped `openspec/specs/text-ink/spec.md:104` demands exactly that; `Color::from_str`'s messages (`src/models.rs:871`, `877`, `923`, `957`) name none of the three fields, so the one path that satisfied this clause no longer does. The tests cannot catch it because the assertion that used to (`msg.contains("invalid ink 'chartreuse'")`) was replaced by `contains("layout[0]")` plus `!contains("unknown field")` (`src/templates.rs:5948-5956`, `src/lib.rs:2776-2778`, `2815-2817`, `2854-2856`, `2992-2994`). Either the errors must carry the field, or the requirement and its two scenarios must be rewritten to claim only what the service does — but a `SHALL` that the diff falsifies cannot land.

2. **The whitespace fix was applied in the shared deserializer and breaks unrelated fields.** `DynamicValueVisitor::visit_str` changed from `trimmed.parse::<T>()` to `v.parse::<T>()`, and the `mm`/`in` path from `trimmed.strip_suffix` to `v.strip_suffix` (`src/models.rs:330-336`). This is generic over every `DynamicValue<T>`, not just `Color`. Verified against `HEAD` and against this tree with the same inputs: `size: [" 10 ", 10]` and `font_weight: " 700 "` both parse on `HEAD` and are now refused (`invalid type: string " 10 ", expected f32`; `invalid type: string " 700 ", expected u16`) [verified by run]. A template in a config dir using either spelling is quarantined by this change. Nothing in `proposal.md`, `design.md`, the three spec deltas or ADR-0093 mentions `font_weight` or the size vocabulary, no delta covers `layout-sizing`, and no test asserts the new refusal. AGENTS.md is explicit that a behaviour change produces a spec delta; this one silently rides a colour change into two other capabilities. Scope the refusal to the colour path (or declare it, with a delta and a test) rather than to every dynamic value.

**Smaller findings, worth fixing while the above are open.**

The `background: null` / `stroke.color: null` refusals in the same task are pre-existing tests (`src/convert.rs:822-830`, `985`), not new coverage.
