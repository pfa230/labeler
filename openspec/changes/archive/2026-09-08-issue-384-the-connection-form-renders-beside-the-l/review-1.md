1. **[P1] Connect can permanently latch onto pre-save data on return.** [design.md:50](/home/pfa/projects/labeler/.worktrees/issue-384/openspec/changes/issue-384-the-connection-form-renders-beside-the-l/design.md:50) retains existing connection-list invalidation, while [design.md:87](/home/pfa/projects/labeler/.worktrees/issue-384/openspec/changes/issue-384-the-connection-form-renders-beside-the-l/design.md:87) explicitly leaves resolution unchanged. That invalidation is not awaited ([connectors.ts:85](/home/pfa/projects/labeler/.worktrees/issue-384/ui/src/api/connectors.ts:85)), and [Connect.tsx:43](/home/pfa/projects/labeler/.worktrees/issue-384/ui/src/pages/Connect.tsx:43) resolves immediately from available cached data. TanStack returns cached data while refetching on remount. ([Documentation](https://tanstack.com/query/latest/docs/framework/react/guides/caching)) Consequently, creating the first enabled connection from Connect’s empty-state link and saving can return to the cached empty list, latch “no connection,” and remain unselected even after refetch succeeds. This contradicts [default-connection/spec.md:192](/home/pfa/projects/labeler/.worktrees/issue-384/openspec/changes/issue-384-the-connection-form-renders-beside-the-l/specs/default-connection/spec.md:192). Specify how successful mutations make the resolution inputs authoritative before Connect latches, including delayed or failed refetches; schema eviction alone cannot do this.

2. **[P1] Separate routes do not prevent mutations from completing while Connect is mounted.** [connections/spec.md:248](/home/pfa/projects/labeler/.worktrees/issue-384/openspec/changes/issue-384-the-connection-form-renders-beside-the-l/specs/connections/spec.md:248) prohibits any mechanism for delivering completed mutations to an open Connect page, and [design.md:94](/home/pfa/projects/labeler/.worktrees/issue-384/openspec/changes/issue-384-the-connection-form-renders-beside-the-l/design.md:94) removes the browse-refresh trigger. However, an operator can start saving and navigate to Connect before the request completes. The existing Cancel remains enabled during saving ([ConnectionsSection.tsx:527](/home/pfa/projects/labeler/.worktrees/issue-384/ui/src/pages/connect/ConnectionsSection.tsx:527)); primary navigation also remains available. Component unmounting does not prevent the mutation’s hook-level completion handling. ([Documentation](https://tanstack.com/query/latest/docs/framework/react/guides/mutations)) Connect can therefore load the old schema and rows before the write finishes, with no planned refresh afterward. The removed contract explicitly covered completion after the form closed ([published connections spec:394](/home/pfa/projects/labeler/.worktrees/issue-384/openspec/specs/connections/spec.md:394)). Rework the mutation/navigation lifecycle and add scenarios for leaving during pending saves and deletes; the assertion that these completions cannot reach an open Connect page is false.
