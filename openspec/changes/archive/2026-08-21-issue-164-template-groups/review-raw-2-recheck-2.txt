    43	
    44	### 1. The group is a YAML field on the template, not a directory and not a store row
    45	
    46	Alternatives were directory mapping (`templates/<group>/x.yaml`) and a row in the SQLite store
    47	beside favorites.
    48	
    49	Directory mapping loses on four counts, all in code that exists today. The loader walks one level
    50	(`src/templates.rs:95`) and every downstream identity is a basename, including `BrokenTemplateSummary.filename`
    51	(`src/models.rs:36`) and the duplicate-id tie-break just frozen in `template-registry` ("the one whose
    52	filename sorts first in byte order"); recursion turns all of those into relative paths and reopens a
    53	requirement written days ago. It puts a caller-supplied string on the write path, where
    54	`template_file_path` currently derives the filename from an id restricted to `[A-Za-z0-9_-]`
    55	(`src/api.rs:310`), so a group segment would need its own traversal, separator, and case-collision
    56	guards on an endpoint that writes files. It turns a regroup into mkdir plus cross-directory rename
    57	plus pruning the emptied directory, with a half-failed state the current single atomic rename does
    58	not have. And it puts the group outside the artifact, so a catalog install (`ui/src/pages/Catalog.tsx:127`
    59	POSTs the YAML body) arrives ungrouped.
    60	
    61	Store metadata fails the portability test the same way, and additionally splits template truth across
    62	a file and a database, which is what ADR-0006 exists to prevent.
    63	
    64	The YAML field costs one field in each of the three parse-path files and nothing else. Its one real
    65	loss: reorganizing `/config/templates` by hand with `mv` does not group anything, because the
    66	directory carries no meaning. Accepted knowingly.
    67	
    68	Recorded as **ADR-0062, "A template's group is a YAML field, not its directory"**.
    69	
    70	### 2. One flat level
    71	
    72	`group` is a single name. The service does not split on `/` or any other character, so

    74

    77	validation, and a depth cap, for a set that is currently a few dozen templates. Widening later is a

    79	cheap option here does not become the wrong one later. Same ADR-0062.

    81	### 3. Validation lives in one function, shared by the parse path and the move endpoint
    82

    84	message naming `group`. It is called from `TemplateDefinition::validate()` (so a bad group quarantines

    86	bad name is a `422` with nothing written). One definition, so the file path and the API path cannot
    87	drift.
    88	
    89	The domain model stores the stripped value: `TemplateDefinition.group: Option<String>`, `raw.rs` gains

    93

   100	use, so the normal path picks an existing name instead of retyping it.
   101	
   102	### 4. Move is `PUT /api/templates/{id}/group`, a targeted single-line file patch
   103	
   104	The endpoint replaces one subresource and is idempotent, which is `PUT`, not `PATCH`.
   105	
   106	The patch is textual, never a parse-and-re-emit, which is what keeps it inside ADR-0006's intent
   107	rather than against it. Under `state.write_lock`, with the path resolved through the registry
   108	(`existing_template_file`), the handler:
   109	
   110	1. reads the stored file;
   111	2. refuses a file holding more than one YAML document (`422`), since "the top-level `group`" is
   112	   ambiguous there, and likewise a file whose root is not a block mapping written one key per line.
   113	   A top-level flow mapping parses fine and has no line to patch or to insert, so reflowing it into
   114	   block style would be exactly the whole-file rewrite this design exists to avoid;
   115	3. finds a top-level `group:` line: a line whose first character is at column 0, that is not a
   116	   comment, and whose key is exactly `group`. Column 0 is what makes a nested `group:` key
   117	   (inside `params`, or a layout item) unreachable, since nested keys are indented;
   118	4. cross-checks that scan against the parsed template. The parser accepts spellings the scan does not
   119	   recognize, `"group": Shipping` among them, so when the parsed template has a group and the scan
   120	   found no line to replace, or found more than one, the handler refuses with `422` instead of
   121	   inserting. Without this check step 7 would append a second top-level `group` key;
   122	5. if the matched line's value is not a scalar it can replace in place (a block scalar `|`/`>`, a
   123	   flow collection, an anchor or alias, or an empty value introducing a nested block), refuses with
   124	   `422` rather than guessing. Plain and quoted scalars are both replaceable, which matters because
   125	   `group: "Shipping"` is a valid and expected spelling;
   126	6. builds the new line as `group: ` plus the name emitted through the YAML serializer, so a name
   127	   needing quotes gets them, and re-attaches any trailing comment the old line carried. Finding that
   128	   comment means skipping a quoted scalar before looking for ` #`, so `group: "A # B"  # keep me`
   129	   keeps both the `#` inside the value and the comment after it; that case is a test, not a comment
   130	   in the code;
   131	7. for a clear, deletes the whole line and its terminator; for an insert, places the new line
   132	   immediately after the top-level `name:` line, falling back to after `id:`, then to the top of the
   133	   document body after any leading comments and `---` marker;
   134	8. parses and validates the patched text, and asserts the group reads back as requested. Only then
   135	   does it write, through the same atomic temp-then-rename as every other template write, and reload
   136	   the registry.
   137	
   138	Step 8 is the safety net that makes the textual patch acceptable: a patch that would produce a file
   139	the service cannot load never reaches the disk. Step 4 is the one that keeps a *loadable* file from
   140	being wrong: a duplicated key can round-trip through a parser that takes the last value, so the
   141	scan-versus-parse disagreement has to be caught before the write, not after it. Line endings are preserved by splitting on line
   142	terminators and keeping each line's own ending, so a CRLF file stays CRLF.
   143	
   144	Recorded as **ADR-0063, "The service may rewrite one key of a hand-authored template"**, which
   145	qualifies ADR-0006: a targeted single-key patch that preserves every other byte is not the lossy
   146	round trip that ADR forbids, and the guarantee is enforced by tests that assert byte equality outside

     8	## ADDED Requirements
     9	
    10	### Requirement: A template declares its group as an optional top-level field
    11	
    12	A template MAY carry a top-level `group` field naming the one group it belongs to. The field is
    13	optional; a template without it is *ungrouped*, and ungrouped is a first-class state, not an error.
    14	
    15	A group name is one flat name. The service SHALL NOT assign meaning to any character inside it: a
    16	name containing `/` is a name, not a path, and produces no hierarchy.
    17	
    18	A `group` value SHALL be valid when, after stripping leading and trailing whitespace, it is:
    19	
    20	- a string;
    21	- non-empty;
    22	- at most 64 characters;
    23	- free of control characters, including tab, carriage return, and line feed.
    24	
    25	The stored group is the whitespace-stripped value. A `group` that is not a string, is empty or
    26	whitespace-only, exceeds 64 characters, or carries a control character SHALL make the template fail
    27	to load, with a parse or validation message naming the `group` field. That quarantines the file
    28	under the existing rules of the `template-registry` capability rather than aborting startup.
    29	
    30	Group names SHALL be compared exactly, including case: `Warehouse` and `warehouse` are two groups.
    31	
    32	The post-change set of top-level template fields is:
    33	
    34	| Field | Type | Notes |
    35	| --- | --- | --- |
    36	| `id` | string | Required, non-empty. Uniqueness across the directory is enforced per `template-registry`. |
    37	| `name` | string | Required, non-empty. |
    38	| `description` | string | Optional. |
    39	| `group` | string | Optional. One flat group name, validated as above. Absent means ungrouped. |

   164	### Requirement: A template is moved between groups without rewriting the rest of its file
   165	
   166	`PUT /api/templates/{id}/group` SHALL set or clear one template's group. The request body is
   167	`{ "group": "<name>" }` to move it into a group, or `{ "group": null }` to make it ungrouped.
   168	
   169	The service SHALL apply the change as a targeted edit of the stored file: it replaces the value of
   170	the existing top-level `group:` line, or, when there is none, inserts one. Every other byte of the
   171	file SHALL be preserved exactly, including comments, key order, indentation style, quoting of other
   172	values, and blank lines. Clearing a group SHALL remove the whole `group:` line.
   173	
   174	The patched text SHALL be parsed and validated before anything is written, and SHALL be written only
   175	if it is a valid template whose group reads back as the requested value. The file SHALL be replaced
   176	atomically, and the registry reloaded, exactly as the other template writes do.
   177	
   178	The service SHALL refuse, with nothing written, any file it cannot patch unambiguously:
   179	
   180	- one holding more than one YAML document;
   181	- one whose top-level `group` value is not a scalar the patch can replace in place. Plain and quoted
   182	  scalars are patchable; a block scalar, a flow collection, an anchor or alias, and a value
   183	  introducing a nested block are not;
   184	- one the template parser reads as already having a group while the patch cannot identify exactly one
   185	  top-level `group:` line to replace, which is what a quoted key (`"group": Shipping`) or any other
   186	  spelling the parser accepts and the patch does not recognize produces. Inserting a second line in
   187	  that case is forbidden: a file SHALL never come back with two top-level `group` keys;
   188	- one whose root is not a block mapping written one key per line, a top-level flow mapping
   189	  (`{id: bin-tag, name: Bin Tag, ...}`) being the case that reaches the parser intact. Such a file
   190	  offers no line to replace and no line to insert, so it is refused rather than reflowed.
   191	
   192	A `group:` key that is not top-level, such as one inside `params` or a layout item, SHALL be left
   193	alone and SHALL NOT be mistaken for the template's group.
