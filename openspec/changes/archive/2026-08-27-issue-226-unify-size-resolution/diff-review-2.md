- **MAJOR — Caps incorrectly modify authored shrinking `to` extents.** `ShrinkingTo` applies `min(cap)` in [resolver.rs:151](/home/pfa/projects/labeler/.worktrees/issue-226/src/resolver.rs:151), although the contract makes it authored and therefore cap-inert ([layout-sizing/spec.md:34](/home/pfa/projects/labeler/.worktrees/issue-226/openspec/changes/issue-226-unify-size-resolution/specs/layout-sizing/spec.md:34)). In a 100-wide frame, `at.x: -20`, `to.x: 90`, `max_w: 5` should preserve the authored 10-unit span but renders only 5.

- **MAJOR — A capped `content` container measures its children against the uncapped frame.** The container measurement path substitutes raw availability for a content axis and ignores `max_w`/`max_h` ([render/mod.rs:1274](/home/pfa/projects/labeler/.worktrees/issue-226/src/render/mod.rs:1274)); final placement later applies the cap ([render/mod.rs:1572](/home/pfa/projects/labeler/.worktrees/issue-226/src/render/mod.rs:1572)). Thus children can wrap, choose a font size, or pass `overflow: fail` against 100 units and then be emitted into a 20-unit capped container, causing silent clipping. Validation does apply the cap ([templates.rs:1408](/home/pfa/projects/labeler/.worktrees/issue-226/src/templates.rs:1408)), so load and render are not the one algorithm required by the spec and checked task 11.0.

- **MAJOR — Line validation mishandles unresolved vertical axes.** Horizontal degeneracy is guarded by `axes_resolved[0]`, but vertical degeneracy always compares placeholder-resolved coordinates ([templates.rs:1309](/home/pfa/projects/labeler/.worktrees/issue-226/src/templates.rs:1309)). Inside a `content`-height container, `at.y: 10` and `to.y: -10` can coincide against the load-time 20-unit probe yet become distinct in the final 10-unit content frame. The template is incorrectly quarantined even though content axes are explicitly unresolved ([layout-sizing/spec.md:432](/home/pfa/projects/labeler/.worktrees/issue-226/openspec/changes/issue-226-unify-size-resolution/specs/layout-sizing/spec.md:432)).

- **MAJOR — Empty text can raise `text_does_not_fit` in a zero-sized chosen box.** Even empty input is modelled as at least one line by `text_fits` and `block_height` ([render/helpers.rs:511](/home/pfa/projects/labeler/.worktrees/issue-226/src/render/helpers.rs:511), [render/helpers.rs:944](/home/pfa/projects/labeler/.worktrees/issue-226/src/render/helpers.rs:944)). In a zero-height/zero-width content box, `overflow: fail` immediately errors and `ellipsis` errors because the marker cannot fit ([render/helpers.rs:646](/home/pfa/projects/labeler/.worktrees/issue-226/src/render/helpers.rs:646)). Empty content should render empty rather than invoke shortening.

- **MAJOR — The OpenAPI schema for `SizeValue` does not match its wire representation.** The manual serializer emits naked `"content"`, `"fill"`, numbers, or parameter-reference strings ([models.rs:396](/home/pfa/projects/labeler/.worktrees/issue-226/src/models.rs:396)), but `ToSchema` is derived on an externally tagged enum with no matching schema/rename attributes ([models.rs:356](/home/pfa/projects/labeler/.worktrees/issue-226/src/models.rs:356)) and registered directly ([openapi.rs:115](/home/pfa/projects/labeler/.worktrees/issue-226/src/openapi.rs:115)). Generated clients therefore see `Content`/`Fill`/`Dynamic` enum shapes rather than the actual API values.

- **MODERATE — SVG intrinsic sizing does not implement all absolute dimensions required by the contract.** The parser recognizes only `in`, `mm`, `cm`, `pt`, `px`, and unitless values ([render/helpers.rs:370](/home/pfa/projects/labeler/.worktrees/issue-226/src/render/helpers.rs:370)). An absolute SVG value such as `width="1pc"` falls through to `viewBox` or `intrinsic_size_undefined`, despite the requirement to convert absolute dimensions into the template unit ([layout-sizing/spec.md:176](/home/pfa/projects/labeler/.worktrees/issue-226/openspec/changes/issue-226-unify-size-resolution/specs/layout-sizing/spec.md:176)).
