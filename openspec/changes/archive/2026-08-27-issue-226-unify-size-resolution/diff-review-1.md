- MAJOR: Rotated-container measurement applies padding on the wrong axes. Measurement subtracts left/right from physical width and top/bottom from physical height before swapping ([src/render/mod.rs:1259](/home/pfa/projects/labeler/.worktrees/issue-226/src/render/mod.rs:1259)); rendering swaps to the author canvas first and then applies padding ([src/render/mod.rs:1832](/home/pfa/projects/labeler/.worktrees/issue-226/src/render/mod.rs:1832)). With asymmetric padding, children are measured against a different box than they receive, producing incorrect wrapping, font size, overflow decisions, and intrinsic sizes.

- MAJOR: Text with a shrinking `to` is not laid out against its resolved box. The measurement path treats every non-`Author` source as the available extent ([src/render/mod.rs:1015](/home/pfa/projects/labeler/.worktrees/issue-226/src/render/mod.rs:1015)), while a shrinking `to` resolves using `to + inset − frame` ([src/resolver.rs:151](/home/pfa/projects/labeler/.worktrees/issue-226/src/resolver.rs:151)). For a 100-wide frame with `at.x: -20` and `to.x: 90`, text is fitted against 20 but rendered into 10, so `overflow: fail` can incorrectly succeed and the final `clip: true` box silently clips it. This violates the unconditional final-box layout contract.

- MAJOR: Runtime-inverted stretching `to` extents lose their required `edge_rect_inverted` error. Frame-source resolution clamps negative availability to zero ([src/resolver.rs:159](/home/pfa/projects/labeler/.worktrees/issue-226/src/resolver.rs:159)), and the renderer only rejects negative resolved dimensions ([src/render/mod.rs:1569](/home/pfa/projects/labeler/.worktrees/issue-226/src/render/mod.rs:1569)). A `to` valid against a default parent width but inverted after a request shrinks that parent can therefore render as an empty box or return `item_out_of_frame`, contrary to the specified reason priority.

- MAJOR: A parameter-resolved authored size of zero is accepted instead of raising `size_invalid`. `resolve` returns authored values unchanged ([src/resolver.rs:149](/home/pfa/projects/labeler/.worktrees/issue-226/src/resolver.rs:149)), but `resolve_placement_box` checks only `< -EPS` and then normalizes the value with `.max(0.0)` ([src/render/mod.rs:1569](/home/pfa/projects/labeler/.worktrees/issue-226/src/render/mod.rs:1569)). Thus `size: ["{box_w}", 10]` with request value `0` can render an empty image/container, despite the explicit contract that any parameter-resolved extent not greater than zero fails.

- MAJOR: A rotated container’s physical frame is itself rotated. The implementation wraps the physical-width/height rectangle in the container rotation ([src/render/mod.rs:1873](/home/pfa/projects/labeler/.worktrees/issue-226/src/render/mod.rs:1873)), although the specification explicitly requires the physical frame outline not to rotate. For 90°/270° non-square containers this swaps the outline footprint and can clip or misplace it.

- MAJOR: Raster intrinsic sizing does not validate dimensions as the declared MIME/extension format. PNG and JPEG are dispatched together, and `raster_image_dimensions` calls `with_guessed_format()` ([src/render/helpers.rs:313](/home/pfa/projects/labeler/.worktrees/issue-226/src/render/helpers.rs:313)). Consequently JPEG bytes labelled `image/png` can supply dimensions successfully, whereas the specification requires `intrinsic_size_undefined` when metadata cannot be parsed as the format claimed.
