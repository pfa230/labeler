1. **MAJOR — The plan expands list elements beyond the accepted string-only contract.** The issue defines an ordered list of strings and explicitly says numeric-looking elements must be quoted (`.agent-runs/issue-213.md:29-37`). The delta instead accepts numbers, booleans, and null in defaults and requests, coercing them to strings (`specs/list-params/spec.md:30-37`, `:114-122`). This also contradicts the parameter table, which calls the default a sequence of strings (`specs/datetime-params/spec.md:78`). The element domain must be reconciled with the issue scope.

2. **MAJOR — The UI work is explicitly outside the issue’s accepted scope.** The issue says the UI is untouched (`.agent-runs/issue-213.md:86-93`), and project rules make the issue body authoritative while requiring newly discovered work to become another issue (`AGENTS.md:86-91`, `openspec/config.yaml:47-51`). The proposal knowingly departs from that scope (`proposal.md:86-90`), and the template-inputs delta mandates new display behavior (`specs/template-inputs/spec.md:233-274`). The proposal cannot authorize its own scope expansion.

3. **MAJOR — Reserving `join` strands stored user configuration without the required migration decision.** `datetime_formats` accepts operator-defined format names (`docs/SPEC.md:1054-1058`), but the plan makes any stored entry named `join` unreachable (`proposal.md:68-70`, `design.md:63-73`). The migration section nevertheless says no stored user data is affected because settings do not carry parameter types (`design.md:184-187`), which misses that `datetime_formats` itself is stored settings data. This conflicts with the repository’s stored-data exception (`AGENTS.md:37-45`). The design must either preserve `{sys.now:join}` as a format, or define a safe stored-data migration and its template consequences.

4. **MAJOR — The consumer inventory omits direct image bindings, leaving the “only through join” guarantee incomplete.** The design claims four live `value_to_string` consumers (`design.md:19-22`), but `image.name` stringifies its data during both measurement and rendering (`src/render/mod.rs:1636-1642`, `:2120-2125`). Nothing in the deltas specifies whether an `image` directly naming a declared list is refused at load or what happens when it names an undeclared array, despite the plan claiming that a list’s only consumer is a text join (`specs/list-params/spec.md:25-28`) and that arrays reaching scalar slots receive the new field-naming refusal (`proposal.md:31-40`). This path needs an explicit contract, validation design, and scenarios.

5. **MAJOR — The undeclared-`when` rule silently removes existing load-time validation without defining the resulting general behavior.** Current validation rejects every `when:` key absent from `params:` (`src/templates.rs:1403-1419`). The new requirement simultaneously says each condition names a parameter (`specs/conditional-visibility/spec.md:10-17`) and permits a key naming an undeclared data field when its request value is an array (`:30-38`). Satisfying the latter necessarily makes undeclared `when:` keys legal for all requests, not only those later carrying arrays. The plan does not explicitly decide the behavior for their scalar, object, and absent values or record the removal and its input-list consequences.

6. **MAJOR — Keeping `scan_tokens` unchanged cannot enforce the promised load refusal for every brace-containing separator.** The design says the scanner remains unchanged and that a brace inside a separator will yield a load refusal naming the scanner-produced token (`design.md:59-61`); the delta also says `{{` is not an escape inside a token (`specs/interpolation-tokens/spec.md:53-67`). The existing scanner, however, globally skips `{{` before looking for tokens and abandons an outer token when it encounters a nested `{` (`src/interpolation.rs:178-219`). Consequently, an attempted token such as `{tags:join('{{')}` produces no token for the structural parser, while non-default brace errors remain render-time by the delta’s own contract (`specs/interpolation-tokens/spec.md:298-316`). The scanner or validation strategy must be redesigned and specified.

VERDICT: REVISE
