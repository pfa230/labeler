1. **MAJOR — The sequence-default change conflicts with `param-resolution` but no delta modifies that capability.** The plan requires every non-`list` sequence default to fail at load (`specs/list-params/spec.md:153-157`; `proposal.md:76-79`). The normative `param-resolution` contract instead says every non-string default is used as written and that literal defaults retain the existing load-time checks (`openspec/specs/param-resolution/spec.md:99-103,135-146`). The proposal omits `param-resolution` from Modified Capabilities (`proposal.md:133-156`), contrary to the rule that changes to an existing requirement use `MODIFIED` (`openspec/config.yaml:66`). Add a complete `MODIFIED` delta for “A declared default is resolved against one request-scoped snapshot,” reconciling its non-string/default-validation clauses with the new load-time refusal.

2. **MAJOR — The input-derivation contract is only partially updated.** The delta modifies “An input list describes the controls one label needs” but not “The service computes an input list for a given label” (`specs/template-inputs/spec.md:1-3`). The latter owns lenient coercion and currently says rendering is unchanged while enumerating render failures for invalid declared values (`openspec/specs/template-inputs/spec.md:217-223,273-277`). This change introduces a new `list` coercion failure and changes a `string` array from accepted/stringified to `400 InvalidRequest` (`specs/list-params/spec.md:120-151,210-226`). Add a complete `MODIFIED` delta for that input-computation requirement, explicitly preserving `200` lenient absorption on `/inputs` for invalid `list` and `string` arrays while stating their render-path failures.

3. **MAJOR — The design intentionally leaves the UI’s API contract types false.** The backend will expose `type: "list"` and array-valued `ParamValue` in template parameters and `param_defaults` (`specs/list-params/spec.md:61-65`; `specs/template-inputs/spec.md:213-218`), yet the design explicitly declines to update the UI type union (`design.md:247-256`; `proposal.md:171-178`). The current declarations accept neither shape (`ui/src/api/types.ts:7,16-23`). Updating `ParamValue` to include `string[]` and `ParamSpec.type` to include `"list"` is API-contract maintenance, not the out-of-scope list form control; `InputControl` can remain unchanged.

4. **MINOR — `default: []` is claimed to remove consequences it cannot remove.** The template-input delta says lists never produce controls or grid columns (`specs/template-inputs/spec.md:31-47`) and then says declaring a default “avoids all three” consequences (`:49-52`). The design likewise says it “removes all three” (`design.md:235-242`). A default prevents omission failures and enables thumbnails, but it does not create a form control, CSV/connector column, or catalog field. Rewrite these claims to distinguish successful default-backed rendering from the intentionally absent input surfaces.
