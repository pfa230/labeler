1. MAJOR — The single-box design violates the clipping contract. The delta requires geometry to govern paint alone and children to remain rectangularly clipped ([spec.md:9](</home/pfa/projects/labeler/.worktrees/issue-287/openspec/changes/issue-287-container-geometry/specs/shape-paint/spec.md:9>)). The design confirms Typst clips a box using its radius ([design.md:18](</home/pfa/projects/labeler/.worktrees/issue-287/openspec/changes/issue-287-container-geometry/design.md:18>)), then proposes putting that radius on the child-holding box ([design.md:76](</home/pfa/projects/labeler/.worktrees/issue-287/openspec/changes/issue-287-container-geometry/design.md:76>)). A rounded rectangle would consequently clip children to its rounded boundary, changing existing rendering and contradicting the “paint alone” rule. The proposed fallback addresses stroke clipping only and incorrectly calls the collapse non-contractual ([design.md:90](</home/pfa/projects/labeler/.worktrees/issue-287/openspec/changes/issue-287-container-geometry/design.md:90>)); both the proposal and issue explicitly require one painted `#box` ([proposal.md:28](</home/pfa/projects/labeler/.worktrees/issue-287/openspec/changes/issue-287-container-geometry/proposal.md:28>), [.agent-runs/issue-287.md:137](</home/pfa/projects/labeler/.worktrees/issue-287/.agent-runs/issue-287.md:137>)). The plan must resolve this incompatibility and make the proposal, contract, and implementation decision agree.

2. MAJOR — The circle validation split misses request-overridable extents. The design says a box judged determinate at load never reaches the render check ([design.md:68](</home/pfa/projects/labeler/.worktrees/issue-287/openspec/changes/issue-287-container-geometry/design.md:68>), [design.md:98](</home/pfa/projects/labeler/.worktrees/issue-287/openspec/changes/issue-287-container-geometry/design.md:98>)), while the render scenario only mentions content/frame extents ([spec.md:61](</home/pfa/projects/labeler/.worktrees/issue-287/openspec/changes/issue-287-container-geometry/specs/shape-paint/spec.md:61>)). However, parameter references are valid authored extents ([layout-sizing/spec.md:14](</home/pfa/projects/labeler/.worktrees/issue-287/openspec/specs/layout-sizing/spec.md:14>)), and request data takes precedence over their defaults ([param-resolution/spec.md:13](</home/pfa/projects/labeler/.worktrees/issue-287/openspec/specs/param-resolution/spec.md:13>)). Thus `size: ["{w}", 12]` with default `w: 12` passes load but a request supplying `w: 14` must still be rejected. The contract and design must require checking every request-dependent resolved box at render, even when its default was square at load.

3. MAJOR — “Use the shared resolver at load” is insufficient and can falsely quarantine content-sized circles. Load cannot measure intrinsic content and deliberately substitutes the available extent, making `content` behave like `fill` ([AGENTS.md:404](</home/pfa/projects/labeler/.worktrees/issue-287/AGENTS.md:404>)). Consequently, a square intrinsic circle inside a non-square available frame can appear non-square to load validation. That contradicts the delta’s assertion that content/frame-dependent squareness is checked at render ([spec.md:24](</home/pfa/projects/labeler/.worktrees/issue-287/openspec/changes/issue-287-container-geometry/specs/shape-paint/spec.md:24>), [spec.md:61](</home/pfa/projects/labeler/.worktrees/issue-287/openspec/changes/issue-287-container-geometry/specs/shape-paint/spec.md:61>)). The plan must define which extent provenance makes a load-time squareness result authoritative and explicitly avoid treating load’s intrinsic-size proxy as the actual circle box.
