# Diff review: issue-263-packed-children

Gates: `cargo fmt --check` clean, `cargo clippy --all-targets --all-features` clean, `cargo test` 642 + 1 acceptance + 1 adr_index passing. [verified]

The core mechanism is right and matches the design. `Anchor::Absent` threads correctly through `available`/`requirement`/`container_inner_axes_resolved` (`src/resolver.rs:163, 229, 260-266`); the accumulation check runs in packing coordinates before the drawing conversion, so `AnchorBeyondFrame`/`ExtentBeyondFrame` both map to `item_out_of_frame` and `AnchorBeforeFrame` is genuinely unreachable for a packed child (`src/render/mod.rs:840, 857`); rotation packs in author space because `container_frames` swaps before `render_items` (`src/render/mod.rs:1846-1856`). `packed_child_sized_identically_to_unpacked_at_origin` asserts byte-identical Typst, which is the strongest test in the change.

## Blocking

**1. Flow overflow raised during measurement names the wrong child.** `src/render/mod.rs:1404-1405` formats `arrange_flow`'s error index straight into the path: `format!("{path}.items[{act_idx}]")`. But `act_idx` indexes `flow_inputs`, built from `active_children` (`:1349-1352`, `when`-filtered), not the template's `items`. The identical call 100 lines below does it correctly: `let (orig_idx, _) = active_items[act_idx];` (`:1501-1503`). Failure: a `size: [fill, fill]` row flow container (demands both axes, so the intrinsic arm runs and errors *before* `render_items`) whose first child is gated off and whose second and third overrun reports `layout[0].items[1]` when the offending child is `layout[0].items[2]`. The spec's overflow scenario requires the error to name the second container; with any gated-off sibling it names a different one.

**2. Task 7.2 is checked, and the artifact standing in for it asserts nothing.** The box claims each acceptance PNG was opened and inspected and that the outcome was *recorded*, "including the case that failed and why, rather than reporting a pass". No such record exists anywhere in `openspec/changes/issue-263-packed-children/` [verified by grep]. What was added instead is `tests/acceptance_issue_263.rs`, one 395-line test named `render_and_inspect_acceptance_evidence` that inspects nothing: of the nine design cases, seven only `.unwrap()` the render and `fs::write` a PNG into `target/`. That is a test that cannot fail, and it is the exact thing `CLAUDE.md` removed under #220 ("Nothing checks this, and no task should claim it... A checked box over it would be a claim nobody can verify and no gate can refuse"). Either uncheck 7.2 and record what the renders showed, or make the file assert geometry.

**3. The headline spec scenarios have no automated assertion.** Missing entirely: "A gated-off child leaves no hole" (the scenario #212 exists for), "An empty value leaves no double gap", "A zero-extent child still draws its frame and still raises its errors", "A quarter turn packs in author space", "Reordering packed children reorders the label", "A packed container with no size fills, and two of them collide", "Every child gated off leaves a padding-sized container". Tasks 5.2 claims the first two. The resolver test that appears to cover them (`src/resolver.rs:917-975`) reaches the gated case through `FlowChildInput { active: false, .. }` — a flag production code never sets: both call sites hardcode `active: true` (`src/render/mod.rs:1396, 1509`) because the `when` filter runs upstream. So the test exercises a branch the service never takes, and the real path is untested.

## Non-blocking

**4. `resolve_packed` is not the single implementation `design.md` promised.** design.md:121-128 names three anchor-resolving sites that must divert to it. Two did (`src/templates.rs:1556`, `src/render/mod.rs:1062`); the third (`resolve_placement_box`, design.md's `render/mod.rs:1501`) was bypassed rather than diverted — `render_items` (`:1473-1489`) and the container intrinsic arm (`:1374-1391`) each inline `source_of` + `resolve` twice. Consequence: at render, a packed child's extents are resolved against the *resolved* inner box with no `fits_frame`, no `ExtentNegative` and no `AuthoredExtentNotPositive` check, i.e. the spec's check 1 never runs against the box the child is actually drawn in. I could not construct a live failure — every non-Author source clamps to `available`, and an Author source flows into `assembled_secondary` so the resolved inner is never smaller — so this is a latent hazard, not a proven bug. Related: `src/resolver.rs:602` clamps a row child's `y` with `.max(0.0)`, silently absorbing a secondary overrun instead of failing loudly.

**5. Agent transcripts sit uncommitted and un-ignored at the worktree root.** `.agy-apply.json` (441 KB), `.agent-review-codex.json`, `.agy-conversation`, `.agent-review-codex.conversation`, `.agent-review-claude.json`. `git check-ignore` returns nothing for all five: `.gitignore`'s `/.worktrees/` is anchored to the repo root and does not match inside the worktree. A `git add -A` on the landing commit puts them in the repository, which is what #244 removed.

**6. ADR-0083 claims a feature this change excludes.** `docs/adr/0083-packed-children-flow-layout.md`, Consequences: "Authors can build dynamic, **auto-wrapping** rows and columns". `wrap` is explicitly out of scope and left in #212; an overrunning row fails with `item_out_of_frame`. ADRs are append-only, so a wrong sentence there is permanent.

**7. Two spellings of the packed-`line` refusal, one dead.** `src/convert.rs:166` (container loop, path `items[N]`) always fires first, making `src/convert.rs:247` (`try_from_raw`, `path: ""`) unreachable. The dead copy would report an empty JSON path if it ever were reached.

**8. `flow:` with a null value silently selects the absolute arrangement.** `flow: {}` is refused with `flow.direction`, but bare `flow:` deserializes to `Option<FlowRaw>::None`, indistinguishable from no `flow` key at all. The spec requires refusal when `direction` is absent.

**9. New panic on a public resolver fn.** `src/resolver.rs:126` `.expect("to placement must have an anchor")`. Unreachable from YAML today only because `convert.rs` refuses `to` on a packed child; unlike `Anchor::resolve`'s panic (task 1.1, deliberate) this one is incidental.
