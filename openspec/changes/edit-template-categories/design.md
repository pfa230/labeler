## Context

See proposal.md for motivation. `Templates.tsx` has a local card component and derives category choices from registry summaries. `useTemplateSource` returns `Response.text()`; `useReplaceTemplate` already PUTs raw YAML, invalidates list/detail and updates the source cache. The backend validates and atomically replaces the source before reloading the registry. `serde_yaml_ng` gives the domain parser no usable source spans, and the UI has no YAML dependency.

Attended research inspected [yaml v2 node ranges](https://eemeli.org/yaml/#content-nodes), [CST documentation](https://github.com/eemeli/yaml/blob/main/docs/07_parsing_yaml.md) and [whole-document formatting limitations](https://github.com/eemeli/yaml/issues/308). A local probe using installed yaml 2.9.1 passed 20 edits over block/flow lists, block/flow roots, absent keys, quoted keys, document markers, indentation, Unicode, CRLF and multiline strings, plus three refusal cases. It is a syntax/range proof, not an application acceptance run.

## Goals / Non-Goals

Reuse source GET and whole-source PUT; category editing remains a client operation. No metadata endpoint, Rust parser/editor, shared-reference rewriting, generic patch framework, autosave, multi-template editing, new category-name normalization or concurrency protocol is required. All category-control behavior stays in the existing templates domain rather than duplicating it in ui.

## Decisions

- **User decision:** Accept ordinary direct category lists and refuse anchor/alias/tag-based category forms with a clear explanation and link to the existing template YAML editor. A demonstrated `categories: &shared [Old]` reused by an enum's `values: *shared` changes that enum when the anchored list changes even though the enum's source bytes are untouched; preserving text alone cannot make that a category-only edit.
- **Routine defaults:** Add an Edit categories button to each card and keep one selected-template editor at Labels level, so Favorites/Recent/grid cards share the same editor. Use one editable string per entry with Add/Remove, Save and Cancel; no comma splitting, trimming or deduplication of values. This avoids making a comma within a category name ambiguous. Keep the editor available after failures. Derive the initial list from the fetched source instead of mixing stale summaries with newer source bytes.
- Add `yaml` v2 as a direct UI dependency (2.9.1 was probed). Parse the fetched document to find the root's literal categories key and its sequence range. Require the supported forms in the delta; parse errors, duplicate/ambiguous keys and indirect/tagged target nodes refuse before PUT. Anchors elsewhere in the file need no rewriting. Regex/line matching cannot distinguish a real key from matching text inside a multiline value, and whole-document serialization changes unrelated formatting.
- Splice a JSON-encoded array of strings into the original JavaScript string at the value range. Use the original range's line terminator when replacing a block sequence: the probe showed its value range includes its final newline, unlike an inline sequence. Leave trailing comments outside the replaced span untouched; comments within the replaced list belong to the deliberate change. An absent key is inserted before the first block-map entry at its indentation, or after the flow-map opening brace with the required separator. Preserve document markers and the remaining source. Send the candidate through the existing PUT/server validation; helper tests prove that its categories match the requested strings.
- Preserve the original fetched text, including a UTF-8 BOM: a local `Response.text()` probe removed it, while `TextDecoder('utf-8', { ignoreBOM: true })` over the response bytes retained it. Update the existing source-read query to use that decoding, and handle a leading BOM when computing the block insertion prefix. Source offsets are JavaScript string offsets; do not convert them to Rust byte positions. Existing whole-source writes already accept the edited text.
- Reuse `useReplaceTemplate` cache behavior to refresh Labels. On success, retain the selected filter if its choice still exists; otherwise select All, because current filtering would retain a hidden Shipping selection after its last category was removed. On refusal/read/write failure show the message without a success notice; Cancel sends no write. No new backend error reason is needed.

## Risks / Trade-offs

The editor supports a bounded source form, not every YAML representation the service may accept. The server remains authoritative for template validation; only the edited array is serialized, so scalar interpretation elsewhere is not changed. Full shared-reference support would need decisions about effects outside categories, which the user excluded.

Promote the demonstrated forms into helper tests with independently written expected source strings, including the next key/comment, and capture the exact PUT body in a Labels interaction test. A whole-document serializer, off-by-one range, lost separator, comma split or false success must fail those assertions. Retain the research's shared-anchor example as a no-write refusal test; do not add a generic YAML compatibility suite.
